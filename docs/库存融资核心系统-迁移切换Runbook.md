# 库存融资核心系统 · 迁移切换 Runbook

> **定位**：主文档 3.8「迁移与切换执行流程」的**操作手册**。流程讲"做什么顺序"，本手册讲"谁、几点、执行什么、看到什么算成功、失败怎么办"。
> **版本**：v1.1　|　**日期**：2026-10-25　|　**v1.1 更新**：2026-10-26（迁移中间态字段补充违约/担保/递减状态）
> **适用**：Rails → Java，**独立库 + 一次性整体迁移**（ADR-004），绞杀者切流（ADR-005）
> **⚠️【预设】说明**：时间、阈值等数值为预设，**必须以演练实测结果替换**后方可执行。

---

## 1. 前提与不可协商的约束

| # | 约束 | 违反后果 |
|---|---|---|
| 1 | **不得影响原有系统运行** | 违反即中止 |
| 2 | **迁移 + 校验 + 切流必须在同一窗口内连续完成** | 中间留时间 = 数据漂移，账务错乱 |
| 3 | 必须在**日终批处理已完成、次日营业尚未开始**的时点切换 | 批处理中途切 → 利息算一半 |
| 4 | 避开月末 / 季末 / **年末决算（日本 3 月）** / 节假日 | 对账复杂化、业务高峰 |
| 5 | 迁移**只读取** Rails 库：不改 schema、不加长期复制槽 | 影响生产库稳定性 |
| 6 | 任一步 Go/No-Go 不通过 → **中止并回滚/改期**，不许带病推进 | 账务事故 |

## 4. 准备期检查清单（T-30d → T-1d）

**演练（必做，≥2 次）**

- ☐ 用**生产规模**数据演练，记录：全量导出耗时、追增量耗时、校验耗时
- ☐ 窗口时长 = 实测总耗时 × **安全系数（⚠️【预设】2～3 倍）**，并预留回滚时间
- ☐ 演练中出现的每一条差异都登记并修复，不允许"看着差不多"

**数据与规则准备**

- ☐ 中间态字段清单确认（`last_interest_date` / `settle_due_date` / `aging_plans.paid_periods` / `aging_days` / `credit_lines.used_amount` / `vehicle_units.status` 含 OVERDUE·DISPOSING / `encumbrance_checked` / `security_records` 进行中登记 / `disposal_cases` 进行中工单）
- ☐ 金额类型如需转换，舍入规则已明确且财务签字
- ☐ 营业日历已导入 Java 库（覆盖切换后至少 1 年）

**业务侧准备**

- ☐ 在途垫款申请已走完或撤回（不留半截状态）
- ☐ 已售待还车辆清单导出，切换后逐台核对倒计时
- ☐ 递减计划进行中的车辆清单导出，切换后逐台核对已还期数
- ☐ 违约处置进行中工单清单导出，切换后逐台核对状态（OVERDUE/DISPOSING）
- ☐ 担保登记进行中清单导出，切换后核对设定/解除状态
- ☐ 通知外部方（厂家/银行/登记）维护窗口，确认对接方配合

**技术准备**

- ☐ 网关路由开关可一键切换，**且切换动作本身演练过**
- ☐ 回滚开关可用（见第 6 节）
- ☐ 监控与告警就位；值班表确认
- ☐ Rails 侧写入冻结脚本/开关就绪

## 5. 切换窗口操作手册

> ⚠️【预设】以下时长为示例，**按演练实测替换**。示例总窗口 4 小时（00:00–04:00 JST）。

| 步骤 | 时间 | 执行人 | 操作 | 成功判据 | 失败处理 |
|---|---|---|---|---|---|
| **T0 冻结写入** | 00:00 | 运维 | 关闭 Rails 写入入口（网关/维护模式）；确认**日终批处理已完成** | Rails 侧新写入 = 0；`batch_runs` 当日作业全部 SUCCESS | 若批处理未完成 → **中止改期** |
| **T0.5 冻结验证** | 00:10 | DBA | 观察 10 分钟，确认无任何新写入（含 cron、后台任务） | 写入计数为 0 | 发现幽灵写入 → 定位并停掉，重新计时 |
| **T1 全量导出 + 追增量** | 00:20 | DBA | 全量导出 → 灌入 Java 库 → **短期** CDC 追增量至追平 | 增量延迟 = 0；复制槽已删除 | 延迟超时（⚠️【预设】>30 min）→ **放弃本次窗口改期** |
| **T2 全量校验** | 01:30 | DBA + 财务 | 行数核对 + **金额合计轧平**（本金/利息/额度占用/冻结） | 全部一致；`diff_amount = 0` | **差异 ≠ 0 → 立即中止**（哪怕差 1 日元） |
| **T3 Go/No-Go** | 02:00 | 总指挥 | 依据 T2 结果 + 各方确认，下达 GO 或 NO-GO | 书面/群内明确记录 | NO-GO → 回滚/改期 |
| **T4 切换路由** | 02:10 | 运维 | 网关切至 Java；开放写入 | 路由生效；健康检查通过 | 立即回滚（回滚窗口内） |
| **T5 冒烟验证** | 02:30 | 开发值班 + 财务 | 抽样验证：台账查询、额度余额、在库清单、计息试算 | 抽样数据与 Rails 冻结前一致 | 异常 → 评估回滚 |
| **T6 开放业务** | 03:00 | 业务负责人 | 通知业务恢复；开放全部入口 | 业务可正常操作 | — |

**每一步必须记录**：执行人、时间、结果、异常。**全部写入切换事件记录**（合规要求，审计会查）。

## 6. 回滚操作

> ⚠️ **关键认知**：回滚**仅在极短窗口内无损**。一旦切换后产生了新业务数据（写入 Java 库），回滚到 Rails 会面临"新数据回不到旧库"。

| 情形 | 处理方式 |
|---|---|
| **T4 后立即发现异常**（尚未产生新业务数据） | 网关切回 Rails → **无损** |
| **已产生新业务数据，但仍在回滚窗口内**（⚠️【预设】首个营业日开始前） | 切回 Rails + **人工补录**窗口内新增业务（需有清单） |
| **超出回滚窗口** | **只能向前修复**，禁止回滚（回滚会造成数据丢失） |

**回滚步骤**
1. 总指挥下达回滚指令
2. 运维切回 Rails 路由
3. DBA 确认 Rails 库数据完整（未被修改）
4. 导出窗口内 Java 侧新增业务清单（如有）→ 人工补录
5. 业务侧确认账务连续
6. 记录回滚事件（时间、原因、影响范围）→ 审计留痕

> **因此切换应选业务低峰**，使窗口内增量尽可能小。

## 7. 切换后（T+1 … T+N）

| 事项 | 频次 | 判据 |
|---|---|---|
| **影子对账** | 每日 | Java 生产结果 vs Rails（只读）影子计算，**日终结果逐项比对** |
| 差异处理 | 实时 | 任何差异登记、定位、修复；不一致不得连续出现 |
| 监控观察 | 持续 | 批处理成功率、对账差异、支付失败、告警数 |
| 回滚开关保持 | 至 T+N | 未确认稳定前不拆除 |
| **下线 Rails** | 连续 N 天（⚠️【预设】N=14）比对一致后 | 财务签字确认 → 下线 |

**下线 Rails 后的收尾**
- ☐ 数据"去共享化"：确认 Java 库为唯一权威源
- ☐ 清理迁移临时对象（临时复制槽、导出文件、临时账号）
- ☐ 归档切换记录（批准人、时点、校验结果、差异处理）
- ☐ 出具**期初期末账务连续性证明**（审计要求）

## 10. 一句话提醒

> 这份 Runbook **设计上合理，但不等于已验证可行**。切换是一次性动作，没有上线后迭代的机会——**尽早做一次生产规模演练**，用实测反过来修正本手册（尤其是耗时、差异项与阈值）。继续打磨文档的边际收益，远低于真跑一次演练。
