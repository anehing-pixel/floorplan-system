# external-api（外部合作方接入面，端口 18090）

> 一句话：**这是给拍卖行、WMS、监管仓等外部合作方用的隔离入口；它现在只有骨架，还没有真正可用的业务接口。**

---

## 它在业务里管什么（目标）

库存融资不只关起门来用。二手车业务需要和外部系统交换数据，例如：

- 拍卖行：落札结果、成交价、车辆信息；
- WMS/监管仓：车辆入库、出库、库存快照；
- 法务局/登记机构：担保登记、抹消结果；
- 银行/征信：回款、征信数据。

这些外部系统不能直接进核心业务库。所以单独设一个**隔离区入口**：

```text
外部合作方
   │
   ▼
external-api :18090（隔离区）
   │
   ▼
integration schema（只存外部往来数据）
   ✕ 不连 public schema（核心业务数据）
```

“隔离区”（DMZ）可以理解为：外部系统只能进这个前台，不能直接进核心账本所在的房间。即使前台被攻破，也拿不到核心业务表。

---

## 规划中的能力（五件套）

| 能力 | 用业务话讲 |
|---|---|
| 入站消息收件箱 | 外部系统发来的报文先落库，带唯一编号/随机数，重复发不会重复处理 |
| 出站任务 | 要发给外部的指令/回执排队，记录发没发、成功没成功 |
| 调用留痕 | 每次外部调用都记：谁、什么时候、发了什么、回了什么 |
| 合作方凭据 | 每个合作方的密钥/证书，加密保存，不写在配置文件里 |
| 密钥轮换与监控 | 密钥定期更换；调用失败/重试可查 |

数据库迁移 **V70–V74（第 70 到第 74 版迁移，建 `integration` schema 下的外部往来表）** 已经把这些表建好。

---

## 它现在实际是什么

**目前只有骨架：**

- 一个启动类；
- 一份配置文件（只连 `integration` schema，不连 `public`）；
- 零 Controller，也就是**没有任何对外业务接口**。

它现在不能：

- 接收拍卖行/WMS 的真实报文；
- 向外部系统发指令；
- 做密钥校验、验签、防重放；
- 提供任何可调用的业务 API。

---

## 它刻意不做什么

- **不经过网关**：它是独立入口，外部合作方不走 `api-gateway`；
- **不连 `public` schema**：核心业务表对它不可见；
- **不装配业务写能力**：不给它业务事件的发布器，避免外部入口能直接改业务账；
- **不把密钥写进配置文件**：密钥应走加密列 + 外部密钥管理/环境变量。

---

## 用一句话总结

> `external-api` 是给外部合作方预留的隔离前台：设计上只碰外部往来数据、不碰核心账本；目前只有启动骨架和表结构，业务接口还没实现，不能对客户说“外部对接已完成”。
