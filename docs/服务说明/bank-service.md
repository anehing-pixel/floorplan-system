# bank-service（银行流水与回款匹配服务，端口 8082）

> 一句话：**银行账上进来一笔钱，它负责判断这笔钱是哪台车、哪笔借据还回来的；有把握就自动对上，没把握就挂人工。**

---

## 它在业务里管什么

经销商卖车后要还款。钱从银行账户进来时，银行流水上通常只有：金额、时间、付款人、附言。系统需要回答：

> 这笔 166.5 万日元的入账，是还哪台车的？还是只是一笔无关的往来款？

`bank-service` 做两件事：

1. **拉流水**：把银行账户的交易明细采集进来，重复拉不会重复入账；
2. **匹配回款**：把每笔流水对到某个 VIN、某笔借据。对上了，再通知额度和担保服务做后续处理。

---

## 它具体做什么

### 1. 采集银行流水

- 按业务日、账户拉取交易明细；
- 同一账户、同一笔银行流水号只入账一次；
- 重复拉取时，重复条数会作为“本来就有”的正常信号返回，不算错误。

### 2. 自动匹配

匹配时主要看两个线索：

| 线索 | 分值 | 说明 |
|---|---|---|
| 流水附言里出现 VIN | 95 分 | VIN 必须同时含字母和数字，避免把订单号、金额误认成 VIN |
| 金额与某笔应还金额完全一致 | 60 分 | 辅助分 |
| 金额接近某笔应还金额 | 45 分 | 只作参考，不足以自动绑定 |

自动绑定要求两个条件同时满足：

1. 最高分 ≥ 90 分；
2. 最高分比第二名至少高 20 分。

达不到就不猜，挂到人工清单。业务上的理由是：**误匹配会同时造成“该收的没收到”和“不该催的催了”，两种错误都很贵。**

### 3. 人工处理

- 人工绑定：运营看着流水，手动指定 VIN/借据；
- 忽略：确认这笔钱和本业务无关；
- 未匹配清单：给贷后工作台逐笔处理。

### 4. 通知后续环节

匹配成功后，`bank-service` 会在同一个数据库事务里写一条“这笔回款已匹配”的通知（事件名 `PAYMENT_MATCHED`，业务键是这笔回款的唯一编号 `paymentRef`），然后：

- **credit-service** 收到后，把可用额度加回来；
- **floorplan-core** 收到后，如果是全额结清，就解除这台车的担保；部分回款不解押。

`bank-service` 自己**不直接改额度、不直接解押**，只负责“把钱和车对上，并发出事实通知”。

---

## 它不做什么

- 不负责真实银行银企直连；当前流水来源是演示数据（`bank-fetch.source=demo`），真实 MT940/CSV 通道未接；
- 不负责建借据、算逾期——那是 loan-service；
- 不负责改额度——那是 credit-service；
- 不负责解除担保——那是 floorplan-core；
- 匹配只做了“VIN + 金额”两层，订单号、时间窗、付款人名称等更细的匹配维度还没做。

---

## 对外提供的操作

| 操作 | 业务含义 |
|---|---|
| `POST /api/jobs/bank-fetch` | 拉取某天、某些账户的银行流水 |
| `POST /api/payments/match` | 对全部未匹配流水跑一次自动匹配 |
| `POST /api/payments/transactions/{id}/match` | 对单笔流水跑自动匹配 |
| `GET /api/payments/matches` | 查匹配结论（可按状态筛） |
| `GET /api/payments/unmatched` | 查挂起待人工的流水 |
| `POST /api/payments/transactions/{id}/manual-match` | 人工把流水绑定到某个 VIN/借据 |
| `POST /api/payments/transactions/{id}/ignore` | 人工判定这笔流水与业务无关 |
| `GET /api/payments/matches/{matchId}/release` | 查这笔匹配对应的解押、额度回补凭证 |

- 流水采集、自动匹配、人工匹配、忽略、未匹配清单都已可用；
- 匹配结论落数据库，重启不丢；
- 查借据走 loan-service 的真实接口（Feign），不是日志存根；
- 匹配成功会真实发出 `PAYMENT_MATCHED`，credit-service 和 floorplan-core 都已接上；
- 仍然是演示流水源，真实银行通道未接；
- 自动匹配只做 VIN + 金额，复杂场景靠人工。

---

## 用一句话总结

> `bank-service` 是“认钱”的服务：把银行进来的钱认到具体车辆和借据上；有把握才自动认，没把握就交给人；认准之后发通知，让额度和担保各自完成后续动作。
