# risk-service（贷后风控与违约处置服务，端口 8084）

> 一句话：**车在库里有没有少、有没有被重复抵押、担保登记有没有过期、经销商违约了怎么收车变现——这些贷后风控的事在这里。**

---

## 它在业务里管什么

金融公司把钱垫出去后，最怕三件事：

1. 车不在库里了，或者被卖掉了却没还款；
2. 同一台车被拿去别处重复融资；
3. 经销商逾期不还，担保登记过期或该抹消的没抹消。

`risk-service` 就是处理这三类贷后风险的：盘点、预警、权属核对、担保台账与登记批次管理、违约处置。

---

## 它具体做什么

### 1. 实地盘点

- 盘点人员到经销商场地逐台扫 VIN，提交盘点结果；
- 系统把“账上有、现场没有”或“现场有、账上没有”的差异记下来；
- 盘点差异会触发风险预警；
- 日本渠道以实地盘点为主要监管手段，不靠扣押钥匙、GPS、封签。

### 2. 风险预警

- 查询预警列表（可按类型筛）；
- 处理预警：降级、升级、关闭，每次处理都留痕；
- 预警目前是“记录 + 人工处理”，还不会自动生成可流转的工单。

### 3. 权属核对（防重复融资）

- 录入某台车的权属核对结果：有没有抵押/查封、有没有在别处融资；
- core 在车辆建账时会看最近一次核对结果，发现已被抵押/查封就拒绝建账；
- 这是“同一台车不能重复融资”的数据来源之一。

### 4. 担保台账与登记批次

- 查担保物台账：某台车是否已放款、已售出、已回款、已解除担保；
- 查“已售出但未回款”的车；
- 查即将到期的担保登记（日本让渡担保登记有 5 年期限）；
- 查待抹消的登记；
- 查证据缺口：合同、登记证明、放款凭证等缺哪份；
- **建担保登记批次**：一批车一次法务局登记，写的是正式登记记录（V10 迁移 `V10__collateral_ledger.sql` 建立的担保登记批次表）；
- **撤销登记批次**分三步：申请 → 执行 → 完成，每步单独留痕，避免一次点击就把登记销掉。

### 5. 违约处置

- 开案：经销商逾期/OOT（车卖了没还款）时开处置案，同时冻结该经销商额度；
- 收车：把车收回；
- 变现：拍卖/转卖，登记变现额；
- 结案：算损失（应收 − 变现），解除额度冻结；
- 撤销：处置不成立时撤销案件，按本单实际冻结的金额精确退回，不多退也不少退。

---

## 它不做什么

- 不负责放款、还款、计息——那是 floorplan-core；
- 不负责算逾期天数——那是 loan-service；
- 不负责付款前的担保登记查询——那是 collateral-reg-service；
- 不负责真正放车——那是 release-service；
- 不自动生成工单：工单表目前只有结构，没有 Java 实现；
- 没有违约通知、法律诉讼阶段等更完整的处置流程。

---

## 对外提供的操作

| 业务分类 | 操作 |
|---|---|
| 盘点 | 提交实地盘点结果 |
| 预警 | 查预警列表、处理预警 |
| 权属核对 | 录入某台车的抵押/查封/重复融资核对结果 |
| 担保台账 | 查台账、查某台车详情、查已售未回款、查到期待抹消、查证据缺口 |
| 登记批次 | 建登记批次、撤销申请/执行/完成 |
| 违约处置 | 开案、收车、变现、结案、撤销 |

具体路径以 `/api/inventory/**`、`/api/alerts/**`、`/api/vehicles/{vin}/lien-check`、`/api/collateral/**`、`/api/disposals/**` 开头。

---

## 现在真实状态（2026-11-24）

- 盘点、预警、权属核对、担保台账查询、登记批次建立与三段式撤销、违约处置五步都已可用；
- 处置开案会冻结额度，结案/撤销会按本单实际增量退回；
- 登记批次写的是正式登记记录，付款前的查询走 collateral-reg-service 的另一个入口；
- 仍然没有：工单体系、违约通知、法律清算阶段、盘点差异自动升级处置；
- 风险规则表 `risk_rules` 目前没有真正的规则引擎读写，预警主要靠人工和批处理。

---

## 用一句话总结

> `risk-service` 是贷后风控岗：盘点在不在、查有没有重复抵押、管担保登记批次和抹消、处置违约车；它记录风险和处置过程，但不负责放款、还款和放车。
