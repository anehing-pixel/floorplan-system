# 管理控制台说明

> 库存融资核心系统 · 前端控制台
> 技术形态：静态 HTML + 原生 JS（零构建、零框架），由 web 服务托管静态资源、**经网关 18080 对外暴露**
> **版本**：v1.3（2026-11-20）｜第 8 节为经销商 CRUD + 名下车辆下钻 + 角色权限；本次同步微服务架构后的访问方式

## 1. 访问方式

> **架构已演进为 Spring Cloud 微服务**：唯一入口是网关，`8080 不再对外开放`。
> 页面和 API 都走网关，同源、无跨域。启动方式见项目根目录 `run-microservices.sh`。

```
http://127.0.0.1:18080/login.html     登录页（网关 → web 静态资源）
http://127.0.0.1:18080/index.html     控制台（未登录自动跳回登录页）
```

先启动服务：`bash run-microservices.sh start`（前台保活，Ctrl+C 停止）。
网关路由里有一条 `console-static` 把 `/`、`/login.html`、`/index.html`、`/css/**`、`/js/**` 转发给 web 服务。

种子账号：见 §8.1 岗位账号表（13 个业务角色各一账号 + 一个一人多岗账号）

> ⚠️ 必须从 **网关 18080** 打开，不要再直连 8080。拆分后 auth/credit/risk 等 Controller
> 已从 web 摘除，直连 8080 打开页面会因接口 404 而功能全废。
> 前端 `API_BASE`（`js/common.js` 与 `login.html`）已改为指向网关，
> 且网关已配全局 CORS——从其他端口/file:// 打开页面也能登录。

## 4. 关键设计说明

### 4.1 为什么不用 Vue / React

| 对比项 | 静态页 + 原生 JS（本方案） | Vue/React SPA |
|---|---|---|
| 构建工具 | 无，浏览器直接打开 | Node + npm + 打包链 |
| 部署 | Spring Boot 静态资源自动托管 | 需额外静态服务器或打包进 jar |
| 改一行看效果 | 刷新浏览器即可 | 重新构建 |
| 适用阶段 | 一期管理后台 | 页面复杂到需要组件化时 |

后端 API 契约（`ApiResponse` 包装 + Bearer 头）已经定好，**未来换前端框架不用动后端**。

### 4.2 三个容易踩的坑

1. **改静态页面必须重新 `mvn package`**
   Spring Boot 从 jar 包内读取静态资源，改 `src/main/resources/static` 不重启等于没改。

2. **金额单位不能写死**
   1 亿日元和 3496 万日元要自动切换单位（`fmt.yenParts`），
   否则会出现「3496.5 万 亿日元」这种错配。

3. **同一个枚举在不同语境含义不同**
   `CLOSED` 在车辆是「已关闭」，在告警是「已处理」——所以告警状态用独立的
   `alertStatusBadge()`，不复用通用 `badge()`。

### 4.3 图表：纯 SVG，零第三方依赖

`common.js` 里的 `chart` 模块手写了三种图表：

- `chart.bar()` 横向条形图（库龄分布、告警类型分布）
- `chart.donut()` 环形图（车辆状态、告警严重度）
- `chart.line()` 折线图（预留）
- `chart.meter()` 进度条（额度使用率，≥70% 黄、≥90% 红）

不引 ECharts/Chart.js 是因为：离线内网环境拿不到 CDN，且一个风控看板用不到
图表库的九成能力。

### 7.1 顺带修掉的两个公共组件 bug（影响全站所有表单）

这两个 bug 是「新增经销商」端到端测试暴露出来的，**存量表单（调评级、冻结额度、
标记售出等）此前都受影响**，一并修复：

**① 必填校验失效**（`common.js` → `formModal`）

```js
// 错误写法：forEach 回调里的 return 只跳出「本次迭代」
Object.keys(inputs).forEach(function (k) {
  if (f.required && v === '') { toast('请填写…'); return false; }  // ← 无效
  values[k] = v;
});
```

后果不只是"没拦住"——必填项校验失败时 `values[k]` **根本没被赋值**，
该 key 在 values 里是 `undefined`。若调用方用 `String(v.x)` 取值，
`String(undefined)` 得到字符串 `"undefined"`——它**非空**，能一路穿过后端的 blank 校验，
最终把 `dealerCode="undefined"` 这种垃圾数据写进主数据表。

**修复**：改用 `for` 循环 + `return false` 真正中断，并显式 `focus()` 到第一个缺失字段。

**② 异步回调必关弹窗**（`common.js` → `modal`）

```js
const r = opts.onOk(body);
if (r !== false) close();   // ← onOk 是 async 时 r 是 Promise，恒不等于 false
```

`onOk` 是 `async function` 时返回 Promise，`Promise !== false` **恒成立**，
所以无论成功失败弹窗都关闭——用户填了一半的表单在报错后被直接丢弃，无法改后重试。

**修复**：检测 thenable，等待 `settle` 后再决定是否关闭；等待期间按钮置灰显示「处理中…」。

### 7.2 后端补的防线：占位垃圾值拦截

`DealerApplicationService.createDealer` 新增 `rejectPlaceholderValue`：

```java
// "undefined" / "null" / "NaN" 这类字面量非空、能过 blank 校验，
// 但会污染授信台账与审计日志 —— 写入前拦住，是最后一道可靠防线。
```

实测：`POST /api/dealers {"dealerCode":"undefined"}` → `VALID_001 经销商编号无效（收到占位值 undefined）`。

**已清理**：库里此前残留 1 条 `dealer_code='undefined'` 的脏记录（id=203，无下游引用）已删除。

### 7.3 另一个渲染缺陷

`businessYears` 为空时后端 JSON 直接省略该字段，JS 取到 `undefined` 而非 `null`，
原来的 `d.businessYears === null` 判断失效，界面渲染出「undefined 年」。
已改为 `=== null || === undefined` 双值判断（`fmt` 系列函数本来就是双值判断，无此问题）。

## 8. 经销商 CRUD 后台 + 名下车辆下钻（2026-10-26 补充）

> 本轮需求：**只有 admin 能编辑经销商信息的 CRUD 后台** + **能看到经销商名下的车辆列表，列表可看车辆具体信息**。
> 三个子需求全部落地，并做了权限边界与引用完整性的双重护栏。

### 8.1 权限模型：RBAC 角色 → 权限点（2026-10-26 升级）

此前是 `ADMIN / USER` 二值角色，已升级为 **13 业务角色 + 23 权限点**的 RBAC 体系。
接口声明所需**权限点**（`@RequirePermission`），角色是权限点的打包，一人多岗取并集。
完整矩阵见《库存融资核心系统-角色与权限矩阵.md》。

**控制台上会用到的岗位账号**：

| 角色 | 账号 | 在控制台里能做什么 |
|---|---|---|
| `SYSTEM_ADMIN` 系统管理员 | `admin / admin123` | 新增/编辑/删除经销商、配置、批处理触发（**不碰业务单据**） |
| `BUSINESS_OPERATOR` 业务经办岗 | `operator / operator123` | 发起垫款申请；看档案与台账 |
| `PURCHASE_OPERATOR` 采购数据录入岗 | `import_op / import123` | 导入采购清单、录入收款账户 |
| `PURCHASE_REVIEWER` 采购审核岗 | `review_op / review123` | 验车确权、实地盘点 |
| `FUNDING_CASHIER` 资金出纳岗 | `cashier / cashier123` | 打款支付 |
| `SETTLEMENT_OFFICER` 结算岗 | `settlement / settle123` | 售出标记、还款核销、结清证明 |
| `COLLECTION_OFFICER` 催收岗 | `collection / collect123` | 库龄递减核销、催收 |
| `DISPOSAL_OFFICER` 违约处置岗 | `disposal / disposal123` | 处置闭环 |

**三道关卡严格区分**：

| 情形 | HTTP | 错误码 | 语义 |
|---|---|---|---|
| 未带令牌 / 令牌失效 | 401 | `AUTH_001` | 认证失败——"你是谁"没过 |
| 令牌有效但权限点不足 | 403 | `AUTH_002` | 授权失败——"你是谁"过了，但"你能干这事"没过 |
| 同一笔业务由同一人自办自批 | 403 | `AUTH_003` | 职责分离——申请人 ≠ 复核人 ≠ 支付人 |

> 前端按角色隐藏按钮只是**体验优化**，真正的边界在后端：
> 用 `operator` 账号直接调写接口，一律 403 `AUTH_002`，不是靠前端拦。

**授权怎么声明**：方法级注解 `@RequireAdmin`，不是路径白名单。

```java
@PutMapping("/{id}")
@RequireAdmin                                   // ← 声明式，跟着方法走
public ApiResponse<Dealer> update(...) { ... }
```

```java
// 拦截器里判定：方法级 或 类级 注解
private boolean requiresAdmin(Object handler) {
    if (handler instanceof HandlerMethod method) {
        return method.hasMethodAnnotation(RequireAdmin.class)
                || method.getBeanType().isAnnotationPresent(RequireAdmin.class);
    }
    return false;
}
```

> **为什么不用路径白名单**：白名单要随着接口增加一条条补，漏配一条就是越权口子；
> 而且改个 URL 就可能绕过。注解跟着方法走，改接口路径不会漏鉴权。

|---|---|---|---|
| Create | 「＋ 新增经销商」 | `POST /api/dealers` | 编号唯一 + 评级口径有效 + 拒绝占位垃圾值 |
| Read | 列表 / 抽屉 | `GET /api/dealers`、`GET /api/dealers/{id}` | 全部角色可读 |
| Update | 行内「编辑」 | `PUT /api/dealers/{id}` | 9 个字段 + 状态机 + 编号查重（排除自身） |
| Delete | 行内「删除」 | `DELETE /api/dealers/{id}` | **带引用完整性护栏** |

**编辑弹窗的 9 个字段**：编号、名称、授信评级、经营年限、状态、联系人、联系电话、营业地址、备注。

**PATCH 语义**（`null` = 不改，空串 = 清空）—— 前端提交时显式区分这两个：

```js
// 前端：空串传 ''（清空），null 不传（不改）
contactPerson: v.contactPerson === '' ? '' : (v.contactPerson ?? null)
```

> 之所以要"空串 = 清空"这个语义：否则前端无法表达"把这个联系方式清掉"——
> 传 null 会被理解成"不改"，字段永远清不掉。

### 8.3 状态机：终止是终态

新增 `DealerStatus` 枚举（`ACTIVE` 正常经营 / `SUSPENDED` 暂停合作 / `TERMINATED` 终止合作），
流转走白名单而非字符串比较：

```java
public boolean canTransitTo(DealerStatus target) {
    if (target == null) return false;
    if (this == target) return true;
    return switch (this) {
        case ACTIVE     -> target == SUSPENDED || target == TERMINATED;
        case SUSPENDED  -> target == ACTIVE || target == TERMINATED;
        case TERMINATED -> false;      // 终态：终止后不可回退
    };
}
```

> 状态值以前散落在准入校验、垫款建账、后台编辑多处，用字符串字面量时
> 拼写错误会**静默失效**（条件永不成立但不报错）。收进枚举后，编译期就能发现。

### 8.4 删除护栏：金融数据不可物理删除

经销商是授信台账主体，删掉会让历史车辆台账与额度流水**失去归属主体、断掉审计链**——
而这些记录要保留多年用于监管追溯。所以：

```java
int vehicleCount = vehicleUnitRepository.countByDealerId(dealerId);
int lineCount    = creditLineRepository.countByDealerId(dealerId);
if (vehicleCount > 0 || lineCount > 0)
    throw new BusinessException(ErrorCode.DEALER_001, Map.of(
        "dealerId", dealerId, "vehicleCount", vehicleCount, "creditLineCount", lineCount,
        "advice", "该经销商名下存在车辆或授信额度，请改为将状态置为「终止合作」而非删除"));
```

界面提示会直接告诉用户**该怎么正确处理**：改用「终止合作」状态。
终止后记录仍在、审计链完整、查询与报表不受影响，同时业务上不再放新单。

### 8.5 名下车辆下钻：一次请求拿全

新增聚合接口 `GET /api/dealers/{id}/vehicles`，一次返回**档案 + 汇总统计 + 车辆明细**：

```
GET /api/dealers/207/vehicles
→ { dealer: {...}, summary: { 16 项统计 }, vehicles: [ ... ] }
```

**为什么是聚合接口**：前端若"先拉经销商 → 再逐台拉详情"，8 台车就是 9 次请求。
聚合后 1 次搞定，而且汇总与明细由后端一次算完，不会出现前端两处口径不一致。

**汇总口径**（4 项金额均可与明细逐行求和交叉验算）：

| 字段 | 含义 | 实测值（冒烟经销商 8 台车） |
|---|---|---|
| `totalInvoiceAmount` | 采购金额合计 | 14,450,000 |
| `totalAdvanceAmount` | 已放垫款合计 | 13,005,000 |
| `totalPrincipalBalance` | **在贷本金**合计 | 8,891,000 |
| `totalPaidPrincipal` | 已还本金合计 | 2,764,000 |
| `vehicleCount` / `inStockCount` / `soldPendingCount` / `settledCount` | 状态分布 | 8 / 5 / 2 / 1 |
| `overdueCount` / `ootCount` | 风险台数 | 1 / 0 |
| `avgAgingDays` / `maxAgingDays` | 平均 / 最长库龄 | 42 / 88 天 |
| `approvedLimit` / `usedAmount` / `frozenAmount` | 授信额度总额 / 已用 / 冻结 | 50,000,000 / 13,005,000 / 0 |

### 8.6 抽屉叠层：从车辆列表点详情能返回

原抽屉是**单例**的：从"名下车辆"抽屉点某台车的详情，详情会**顶掉**列表，关掉就回不去了。
改成了叠层抽屉：

```js
let drawerSeq = 0;
function drawer(title, contentHtml) {
    const seq = ++drawerSeq;
    const z = 90 + seq * 2;
    const mask = el('div', { class: 'drawer-mask' }); mask.style.zIndex = String(z);
    const box   = el('div', { class: 'drawer' });       box.style.zIndex   = String(z + 1);
    // 每次新建独立 mask/box，closeDrawer 只移除自己那层
}
```

现在：从车辆列表点「详情」弹出第 2 层 → 关闭详情 → **回到第 1 层的车辆列表**，列表状态不丢。
