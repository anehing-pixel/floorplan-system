# 作业定时调度与多实例锁（2026-11-24 落地）

> 状态：**已实现**。调度器、配置键、prod 启动检查、Redis 实例脚本与 `redis-smoke` 均已落地。
> 作业的**精确时刻**仍属 `[待定源]`：本文给的是可运行的默认值，签字后只改配置，不改代码。
> 唯一事实来源仍是 `PROGRESS.md`。

---

## 1. 设计选择

| 选择 | 结论 | 理由 |
|---|---|---|
| 调度框架 | **Spring `@Scheduled`**（不加 Quartz） | 当前作业都是"每日/每 15 分钟一次"的固定 cron，不需要运行时改 cron、任务依赖图或 Quartz 的集群表；Spring 调度 + 分布式锁已满足"不重复执行" |
| 多实例互斥 | **`DistributedLock`**（本地 memory / 生产 redis） | 作业是外部/批量副作用，锁只保效率；真正的正确性仍靠 `batch_runs` / `interest_ledger` / `uk_payment_txn` 唯一约束 |
| 锁失败语义 | **fail-closed** | 锁服务不可用时跳过本轮，不无锁裸奔；少跑可以补，重复入账收不回 |
| 开关默认 | `floorplan.jobs.enabled=false`（本地） | 本地冒烟不让 cron 干扰测试数据 |
| 生产强制 | **prod profile 启动检查要求 `true`** | 防止"以为调度在跑，实际永远不跑"（`ProductionReadinessCheck`） |
| 锁 provider | 本地 `memory`，生产必须 `redis` | prod 检查拒绝 `lock.provider=memory` |

## 2. 已接的作业

| 作业 | 进程 | 默认 cron（JST） | 配置键 | 锁 key / 幂等 |
|---|---|---|---|---|
| `DAILY_INTEREST` 日终计息 | web | `0 50 23 * * *` | `floorplan.jobs.interest.cron` | `lock:job:DAILY_INTEREST:<bizDate>`；`interest_ledger(vin,biz_date)` |
| `AGING_ADVANCE` 库龄推进 | web | `0 0 1 * * *` | `floorplan.jobs.aging.cron` | `lock:job:AGING_ADVANCE:<bizDate>`；`batch_runs` |
| `AGING_REDUCTION_DUE` 递减计划 | web | `0 30 1 * * *` | `floorplan.jobs.aging-reduction.cron` | `lock:job:AGING_REDUCTION_DUE:<bizDate>`；`batch_runs` |
| `SETTLE_WINDOW_SCAN` 结算窗口 | web | `0 0 2 * * *` | `floorplan.jobs.settlement-scan.cron` | `lock:job:SETTLE_WINDOW_SCAN:<bizDate>`；`batch_runs` |
| `DEFAULT_DISPOSAL` 自动开处置单 | web | `0 30 2 * * *` | `floorplan.jobs.disposal.cron` | `lock:job:DEFAULT_DISPOSAL:<bizDate>`；`batch_runs` |
| `ANNUAL_REVIEW_SCAN` 额度年审 | web | `0 0 3 * * *` | `floorplan.jobs.annual-review-scan.cron` | `lock:job:ANNUAL_REVIEW_SCAN:<bizDate>`；`batch_runs` |
| `INTEREST_ARCHIVE` 季度归档 | web | `0 0 4 1 1,4,7,10 *` | `floorplan.jobs.archive.cron` | `lock:job:INTEREST_ARCHIVE:<bizDate>`；`batch_runs` |
| `BANK_FETCH` 银行采集 | bank | `0 */15 * * * *` | `floorplan.jobs.bank-fetch.cron` | 服务内按账户加锁（`lock:bank:fetch:<account>:<date>`）；`uk_payment_txn` |
| `DPD_REFRESH` DPD 刷新 | loan | `0 30 0 * * *` | `floorplan.jobs.dpd-refresh.cron` | `lock:job:DPD_REFRESH:<date>`；按 asOf 幂等 |

> **bizDate 口径**：调度器用 `LocalDate.now(Asia/Tokyo)`。计息在 23:50 跑当天，
> 其余日终作业在次日凌晨跑"新的一天"；BANK_FETCH 的窗口由服务自身的 `lookback-days` 决定。
> 如果业务要求"凌晨跑前一天"，改 `@Scheduled` 方法里的 bizDate 计算——这属 `[待定源]`，
> 不要用配置键把两种口径混在一起。

## 3. 怎么开

### 3.1 本地（单实例，不跑 cron）

默认即关闭；`bash run-microservices.sh smoke` 不受影响。

### 3.2 生产（必须）

```bash
export SPRING_PROFILES_ACTIVE=prod
export FLOORPLAN_JOBS_ENABLED=true
export LOCK_PROVIDER=redis
export FLOORPLAN_JWT_SECRET=...          # 强密钥（prod 检查）
export SPRING_DATASOURCE_PASSWORD=...    # 非默认（prod 检查）
export PAYMENT_WEBHOOK_SECRET=...        # 非默认（prod 检查）
export ATTACHMENTS_S3_BUCKET=...         # 非空（prod 检查）
```

`ProductionReadinessCheck` 在 prod profile 下会拒绝以下任一：
JWT/webhook/DB/账户/附件弱默认值、`lock.provider=memory`、`bank-fetch.source=demo`、
`floorplan.jobs.enabled=false`。

### 3.3 本地验证 Redis 锁

```bash
bash run-redis.sh                 # 启动 floorplan-redis（Docker）
bash run-microservices.sh redis-smoke   # 以 LOCK_PROVIDER=redis 起服务 + 跑断言
bash run-redis.sh stop            # 可选：停止
```

`redis-smoke` 断言 `BANK_FETCH` 响应 `lockProvider=redis`，并并发触发两次确认无 500。
多进程互斥的强证明由 `RedisDistributedLock` 的 `SET NX` + Lua 释放保证（另有单测）。

## 5. 多实例边界

- **锁只保效率**：作业内部仍靠唯一约束/幂等键保证正确性；锁过期、Redis 主从切换丢锁
  最多导致重复跑一次，不会造成重复入账（前提是作业本身幂等）。
- **锁不续期**：TTL（web/loan 30 分钟）必须大于作业最长耗时。超时后另一实例可接管；
  作业幂等是硬前提。
- **Quartz 何时需要**：需要运行时改 cron、任务依赖图、失败告警/暂停/恢复、集群选主时，
  再引入 Quartz（或 XXL-JOB）；当前 Spring `@Scheduled` + DB 幂等 + Redis 锁已覆盖。
- **Redis 高可用**：本地是单容器；生产需要 Sentinel/Cluster + 持久化。Redis 本身不存业务数据，
  丢失只影响锁租约，但主从切换会短暂出现双持有者——由作业幂等兜底。
