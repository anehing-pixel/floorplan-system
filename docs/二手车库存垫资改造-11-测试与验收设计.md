## 2. 端到端主用例 E2E-0（需求书 §11.1 逐步断言）

数据基线（与需求书一致，可复核）：落札価 **2,000,000** / 評価点 **4.5** / 修復歴 **無** / 車検残 **18 月** /

| 10 | 重估跌至 1,300,000 | `LTV_BREACH_DETECTED` | `topup_required_amount>0`；按 D08 §7 公式算出期望值（**断言写具体数字，不写 >0**） |

> **步 11 的冲抵顺序断言需要裁决**：需求书 §11.1 写「冲抵（息→本）」，
> 而 R8.2 的九步与 D05/D06 写「费用 → 利息 → 本金」。两者不等价（先扣息会让费用挂账）。
> **本文按 D08 的「余额口径」不预设顺序，改为断言「冲抵明细之和 = 回款额，且本金减少额可解释」**，
> 并把顺序本身列为待裁决项（登记进 D12 §7 的 D11 前置输入）。这是我在写断言时发现的两处文档口径不一致之一，**不掩盖**。

### 4.1 补充实验 E-1：集成链路中断时业务不被追溯改判（ADR 4.1 推论 ②）

> 这条**不是 INV-5 的另一种说法**，而是「业务结论只由核心库决定，集成库只决定结论能不能被推进」
> 的可执行版本，因此单列编号，避免与 D02 §5.6 的 INV 定义混用。

| 实验 | 期望 |
|---|---|
| `external-api` 停机 + `integration` 置只读，跑 E2E-0 后半段 | 已生效的 `PARTNER_RECEIPT` **仍有效**，台账不因 DMZ 不可用而回退 |
| 同上状态下降新放款 | **成功**（outbox 与入站解耦，放款不依赖 DMZ）；出站任务留 `PENDING` |
| 恢复 DMZ 后 | 积压任务按序补齐，`SUCCESS`；不产生重复任务（P5） |
| `UPDATE integration.partners SET status='SUSPENDED'` 后重跑已归档回执 | 已产生的 `PARTNER_RECEIPT` 不追溯作废（partner 状态只影响**新**调用）；但新调用被拒 `PTNR_002` |
| 把某条已被引用的 `inbound_messages` 行删掉 | **必须失败**（`release_receipts.inbound_message_id` 外键 / RESTRICT），证明证据链不可拆 |

> 说明：最后一条是有意设计成"失败"的——如果删掉证据行业务还能跑，说明 INV-5 的
> "回执记录只能由 DMZ 消息路径产生"没有真正落地（证据链退化成一个可随意摘除的字符串）。

合计 **≥ 164** 条（含重复覆盖的余量）；**断言数随开发增长，不得把总数写死在脚本或文档里**（AGENTS.md §5）。

### 9.2 每条断言的最低要求

1. 经 **gateway 18080** 打到对应服务（不是 localhost:8080 直连），验证「路由真实可用」；
   对外部端点则经 `external-api:18090`，并**同时**断言 `integration.call_logs` 有对应记录。
2. 写断言不仅断言 HTTP 2xx，还要**回读 DB 事实**（列值级别，不是行数级别）。
3. 涉及事件的断言必须包含「消费幂等」半边（同事件二次投递无副作用）。
4. 涉及状态的断言必须包含一条**非法转移被拒**。
5. 脚本自清理，可重复执行（幂等），不依赖执行顺序（除 E2E-0 内部步骤）。

### 9.3 禁止的"绿色"

| 禁止 | 原因 |
|---|---|
| 只断言端点返回 200 | 项目历史上「端点存在、网关 404」踩过三次 |
| 用 `-DskipTests` 的编译当验收 | AGENTS.md §5 明令 |
| 断言写「不报错」而不是写期望值 | 掩盖默认值/兜底路径 |
| 把 LEGACY 断言改成 USED 期望 | L2 保护清单 |
| 用被测公式计算期望值再比较 | 循环论证，公式改错断言跟着错 |
| 为让冒烟变绿而放宽 CHECK / 删除约束 | 等于用可配置旁路退化为软放行（AGENTS.md §12） |

### 9.4 完成判据（Definition of Done）

```
一个 USED 工作包「完成」=
  ① mvn -B clean package 全 SUCCESS
  ② bash run-microservices.sh smoke EXIT 0 且 FAIL = 0
  ③ 本包的 scripts/smoke_used_*.py 已存在且被收口方合并
  ④ 该包覆盖的 A/INV/P 编号清单逐条有对应断言（缺口须显式列出，不许沉默）
  ⑤ 未越写入集（git diff --name-only 对照 D12 任务卡）
  ⑥ 并行期在自己 schema 内跑：agent_env.sh init/env/check 过表数门槛
     （FLOORPLAN_PUBLIC_TABLES 按 D04 §2.1 阶梯设 73/84/89/94/96，不许沿用默认 67），
     且隔离守卫 2 条通过：current_schema == 目标 schema、public 一行未动
  ⑦ **并发与幂等类断言（P1–P20、乐观锁、SKIP LOCKED、部分唯一索引、outbox 去重）
     必须在合并后的 public 主干全量回归再跑一次**；各分支 schema 的绿灯不作为这些断言的结论
  ⑧ PROGRESS.md 由收口方更新（本 agent 不写）
```

> **判据分层（用户规矩 2026-11-22 + `docs/并行开发-W1环境隔离.md §5`）**：
> 并行期一人一套 DB schema 是为「别互相踩」，不是为证明集成没问题；
> **唯一交付判据是合并后在 `public` 上那一次全量回归**
> （`unset FLOORPLAN_DB_SCHEMA SPRING_DATASOURCE_URL` → 偏移 0 → `run-microservices.sh smoke`，EXIT 0、FAIL=0）。
> 守卫断言任一失败时那一轮**全部断言不作数**（不是「少两条红」）；忘 `unset` 的后果是整条主干回归
> 其实跑在别人留下的 schema 上。DMZ 侧还有一处：`integration` 五张表是全局队列与幂等表，
> 并行同样互踩，故 INV-1/A5 的最终结论只在主干那次算（D12 §4.1 末行）。
> **基线标签规矩**：新基线一律 `base-<波次>-<日期>`（如 `base-wu1-20261201`），现存 `wave0*` 不改名。
