# 剩余需求并行开发拆分方案

> 基线：`HEAD d1c90e8`（2026-11-22 本轮全仓复核时点）。
> 本文只解决「怎么拆」，不重复「缺什么」——缺口清单见 `PROGRESS.md` §8 与本轮复核结论。
> 与旧方案的关系：`库存融资核心系统-多Agent并行开发拆分方案.md` 是 Wave 0/Wave 1 的历史方案（已完成），
> 本文是**剩余需求**的续篇，沿用其「写入集互斥 + 契约先行 + 号段预分配」三条纪律。

## 0. 结论

**能拆，最大并行度 5，但不能按功能一人一块。**

剩余需求的耦合点全部在**机制层与共享层**，不在服务目录：

- 五个服务（loan / bank / release / credit / recon）的目录天然互斥，可以真并行；
- 但「跨服务触发」这件事本身没有任何实现，任何一个 agent 单独做都做不完；
- 共享层的 `AdvanceApplicationService` 一个类同时承载放款、门禁、放款前置三件事，多人同改必冲突。

所以顺序是：

```
W0 地基（1 agent 串行） → W1 五个服务（5 agent 并行） → W2 共享层+前端（3 agent 并行） → W3 收口（1 agent 串行）
```

每波有硬门禁，不过门禁不进下一波。共 10 个 agent，其中 1 个是收口角色。

## 1. 三处硬耦合（决定拆分边界，不要试图绕开）

| 耦合 | 实测现状 | 对拆分的硬约束 |
|---|---|---|
| **事件机制** | `outbox_events` 表 + `OutboxPublisher` 接口在；**0 实现类、全仓 0 个 `@Scheduled`、0 个消费者、0 幂等表** | 「放款→借据→回款→解押→回补」整条链都依赖它。必须先由 1 个 agent 做完并冻结契约，否则 5 个 agent 会各自造一套假触发 |
| **本地跨服务调用** | 9 个服务 `discovery.fail-fast=false`；网关靠 `ROUTE_*` 直连；Feign 只有 `lb://`（`@FeignClient(name=...)` 无 `url`），全仓无 simple discovery 配置 | 本地不启 Nacos 时 Feign 解析不到实例 → agent 只能对着存根测 → 必然复现「写了代码没接通」（`/api/payments/**` 被 core 兜底 404 就是这类）。地基波必须补「本地直连」开关 |
| **共享层已有类** | `application/`、`domain/`、`common/` 被全部服务依赖；`AdvanceApplicationService` 一个类承载 放款 + 门禁 + 前置校验 | 共享层**已有文件只允许一个 owner**；新增包可以并行，改已有类不行 |

```
W0  事件机制 + 本地直连 + 契约冻结 + 幂等表
 │
 ├──► W1-LOAN     借据消费 LOAN_CREATED，暴露 GET /api/loans/by-vin/{vin}
 │        │

 │        │
 ├──► W1-RELEASE  消费 PAYMENT_MATCHED → 建出库指令草稿（不自动放车）
 │        │
 └──► W1-RECON    只依赖自身表，与上面完全解耦
```

## 8. 验证协议（防「假绿」）

1. **判据不是 exit 0，而是业务语义**。断言必须校验响应里的业务字段（`status` / `loans.id` / `event_type`）；
   只判 HTTP 200 会把 core 兜底的「资源不存在」当通过——`/api/payments/**` 404 就是这么漏掉的。
2. **新增端点必须同步交付脚本**，放 `scripts/smoke_<agent>.py`，能独立跑（自己登录拿 token）。
3. **只起必要的服务**：W1 agent 起 `web + 自己的服务 + 被依赖服务`，不要动 10 个服务全量冒烟。
4. **全量冒烟串行**：只有 W3 跑 `run-microservices.sh smoke`，避免抢 5434 端口和 DB。
5. **编译验证按模块**：`mvn -q -pl <module> -am test`，不要每次全仓 `clean package`（并行时会抢文件锁）。

## 9. 六件不要并行的事

| # | 事项 | 原因 |
|---|---|---|
| 1 | 事件机制本身 | 所有跨服务任务的公共前置，拆开做等于各造一套 |
| 2 | 共享层已有类的修改 | `AdvanceApplicationService` / `CollateralLedgerApplicationService` 一处承载多职责，多人改必冲突 |
| 3 | 迁移号段协商 | 撞号会让 Flyway 拒绝启动，整个环境不可用 |
| 4 | 门禁开关开启 | 开关一开，任何前置缺陷都会变成「全量拒付」，必须等放款前置落地后一次性开 |
| 5 | 物理拆库 | 现在靠共库保住的原子性，拆库会一次性断掉；必须等事件机制与 outbox 消费验证通过 |
| 6 | 全量冒烟执行 | 抢端口/DB，且结论不可比 |
