> **版本**：v1.2　|　**日期**：2026-10-26　|　**v1.2 更新**：2026-10-26（新增 3.22 节：V4/V5/V6 迁移的 users 表、dealers 档案列扩展、insurance_policies 补列）

## 1. 全局设计约定

| 约定项 | 规则 | 理由 |
|---|---|---|
| 金额类型 | 一律 `bigint`（整数日元），映射 Java `long` | 日元无小数，彻底消灭浮点误差 |
| 比率/利率类型 | `numeric(p,s)` 定点（如 `numeric(5,4)`、`numeric(7,4)`） | 利率、垫款比例需保留精度；**但落到金额字段必须量化为整数日元** |
| 时间类型 | `timestamptz`（带时区），业务日期用 `date` | 全系统统一 JST；业务日以营业日历为准 |
| 主键 | 业务实体用 `bigserial`；车辆单元用 **VIN 作业务主键** | 单台独立核算，VIN 是天然主键 |
| 删除 | **不做物理删除、不用软删标记**；状态由生命周期字段表达 | 金融账务须保留完整轨迹 |
| 审计 | `audit_events` 为 **append-only**，仅授予 INSERT | 审计链不可篡改 |
| 并发 | 额度/车辆单元加 `version` 乐观锁；额度占用用 `SELECT ... FOR UPDATE` 行锁 | 禁止无锁的读-改-写 |
| 幂等 | 写接口的 `idempotency_key` 建**唯一索引** | 数据库层兜底防重复垫款/重复还款 |

### 3.9 audit_events（审计事件，append-only）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | bigserial PK | |
| `actor` | varchar(64) | **操作人登录名**（如 `admin`）——服务端验签的令牌身份，不可伪造 |
| `actor_role` | varchar(32) | 操作人角色（`ADMIN` / `USER`）；系统操作为空 |
| `action` | varchar(32) | 动作类型 |
| `target_type` / `target_id` | varchar(32) / varchar(64) | 目标对象 |
| `before_snapshot` / `after_snapshot` | text | 变更前后快照（`key=value` 串，非 JSON） |
| `trace_id` | varchar(64) | 链路追踪（与运行日志、HTTP 响应体同号） |
| `created_at` | timestamptz NOT NULL | |

**权限约束**：仅授予 `INSERT`，不授予 `UPDATE` / `DELETE`（可用数据库角色或应用层权限双重保证）。

**操作人来源（2026-10-26 修复）**：
`actor` 原先取自请求头 `X-Operator-Id` —— **客户端可任意伪造**，审计链形同虚设。
现由 `web/.../config/AuditActor.java` 统一解析，优先级：

| 优先级 | 来源 | 可信度 |
|---|---|---|
| 1 | 令牌身份（`authUsername`，服务端验签） | ✅ 不可伪造 |
| 2 | 请求头 `X-Operator-Id` | ⚠️ 仅无令牌场景兜底（定时作业） |
| 3 | 字面量 `system` | 系统操作 |

`actor_role` 按 `actor` 反查 `users.role` 自动补齐——
内控铁律"发起与执行分离"要能验证，靠的就是角色差异。

> **历史数据不回填**：修复前的 `actor` 存的是客户端传的假值
> （`1` / `verify-script` / `repair`），真实身份客观上已不存在。
> append-only 表改写历史会破坏审计原则，硬填一个"看起来对"的值
> 反而是在审计表里写入新的不实信息。排查时以 `actor_role IS NOT NULL` 作为可信判据。

| 项 | 值 | 理由 |

| 列宽 | `VARCHAR(20)` → `VARCHAR(40)`（V9 迁移，最长角色码 `RISK_ADVISORY_OFFICER` 22 字符） |
| 语义 | 由 `ADMIN`/`USER` 二值改为 **`UserRole` 枚举名**（如 `SYSTEM_ADMIN` / `BUSINESS_OPERATOR`） |
| 回填 | `ADMIN` → `SYSTEM_ADMIN`；`USER` → `BUSINESS_OPERATOR`（历史上它实际能做的正是发起垫款申请） |
| 定位 | **仅作主角色与审计展示用**；真正的授权判定读 `user_roles` |

> **为什么保留单值列**：既有审计字段 `actor_role` 与历史令牌载荷依赖它，
> 删列会连带改审计链。保留它做"主角色"，授权判定另走 `user_roles`，职责清晰。

#### 3.24.3 advances 的三段责任链列（V8 新增）

| 字段 | 类型 | 说明 |
|---|---|---|
| `applicant` | varchar(64) | 垫款申请人（自然人，来自服务端验签的令牌身份） |
| `reviewer` | varchar(64) | 垫款复核人（自然人，须 ≠ applicant） |
| `reviewed_at` | timestamptz | 复核时间 |
| `disburser` | varchar(64) | 支付人（自然人，须 ≠ applicant 且 ≠ reviewer） |

> 三个字段构成完整责任链。**记自然人而非只记角色**：一人多岗时同一角色可能既发起又复核，
> 角色看不出差异，但审计要能回答"这笔到底是谁经手的"。

#### 3.24.4 alerts 的处置留痕列（V8 新增）

| 字段 | 类型 | 说明 |
|---|---|---|
| `handler` | varchar(64) | 告警处置人（自然人） |
| `handled_at` | timestamptz | 处置时间 |
| `handle_note` | text | 处置说明：为什么这样处置，供事后复核 |

#### 3.24.5 V9 种子账号

V9 补齐了 V8 遗漏的岗位账号（授信审查岗 / 增信业务岗 / 贷后管理岗 / 催收岗 / 担保管理岗），
使冒烟测试的每个业务动作都能用**该动作真正该由谁做**的账号来发——
而不是拿管理员账号代劳（那会绕过"管理员不碰业务单据"的设计前提）。

## 4. 并发控制设计

| 场景 | 机制 |
|---|---|
| 额度占用（垫款） | `SELECT ... FOR UPDATE` 行锁锁定 `credit_lines` 该行 → 校验 → 更新 `used_amount` → 提交。**禁止无锁读-改-写** |
| 额度释放（还款） | 同上，行锁下扣减 `used_amount` |
| 车辆单元状态流转 | `version` 乐观锁 + 状态机合法性校验，失败重试 |
| 重复计息 | `interest_ledger(vin, biz_date)` 唯一约束 + 作业幂等 |
| 重复还款/垫款 | `idempotency_key` 唯一索引（数据库层兜底） |

> **默认（ADR-006）**：垫款与额度占用同事务回滚（已实现并经冒烟验证）。若二期改异步，需增加 `payment_status` 字段与补偿状态机，本表结构需相应调整。

## 5. 数据迁移相关约定

1. **基线**：本设计为 Java 侧目标 schema；迁移前须以 **Rails 实际 schema 为基线**核对（见"Rails 现状盘点"核对项）。
2. **唯一改 schema 的窗口**：按 ADR-004，一次性整体迁移是可合法调整类型的时机（如金额类型）。若调整，必须在迁移脚本中定义**明确舍入规则**（日元无小数，只舍入一次），且对账可解释。
3. **迁移必带的中间态字段**（防切换后算错）：
   - `vehicle_units.last_interest_date`（最后计息日）
   - `vehicle_units.settle_due_date`（结算窗口到期日）
   - `aging_plans.paid_periods`（递减已还期数）
   - `vehicle_units.aging_days`（库龄）
   - `credit_lines.used_amount`（已占用额度）
   - `vehicle_units.status`（含 `OVERDUE`/`DISPOSING` 等违约中途态，须完整迁移）
   - `vehicle_units.encumbrance_checked` / `duplicate_financed`（权属校验结果）
   - `security_records` 进行中的担保登记（含 `doc_status`）
   - `disposal_cases` 进行中的违约处置工单（若有）
4. **审计表迁移**：`audit_events` 迁移后仍须保持 append-only，不得因迁移产生断链。
