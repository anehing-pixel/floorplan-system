# 接口契约 · V16 借据（LOAN agent ↔ PAYMENT agent）

> 状态：**冻结（FROZEN）** · 版本：V16 · 维护方：loan agent · 消费方：payment agent
>
> 本文件是跨 agent 契约。字段名、类型、JSON 结构一经写定不得改动；需要变更必须显式通知对端并升版本。
> 设计依据：`docs/贷后风险分层-借据事件与经销商画像设计.md`、`docs/库存融资核心系统-ADR008逾期状态归属借据设计.md`。

---

## 0. 一句话

**payment agent 在回款匹配出 VIN 后，调 `GET /api/loans/by-vin/{vin}` 拿到该 VIN 当前未结清的借据，用返回的 `advance_id` / `dealer_id` / `status` / `due_date` 完成核销与额度回补的判定。**

映射规则：**一笔垫款对应一个借据（`loan.advance_id` → `advances.id`）；一个 VIN 唯一指向一笔未结清借据**（见 §3）。

## 1. `loans` 表完整 DDL（字段名 + 类型，契约字段已标注）

> 金额一律 `BIGINT`（整数日元）。契约字段在注释里标 `【契约】`——合同 freeze 的就是这些名字与类型。

```sql
CREATE TABLE IF NOT EXISTS loans (
    id                  BIGSERIAL PRIMARY KEY,                -- 【契约】借据主键
    loan_no             VARCHAR(32)  UNIQUE NOT NULL,
    advance_id          BIGINT,                              -- 【契约】资金来源凭证 → advances.id
    vin                 VARCHAR(32)  NOT NULL,               -- 【契约】车架号，匹配入口
    dealer_id           BIGINT       NOT NULL,               -- 【契约】经销商 ID
    credit_line_id      BIGINT       NOT NULL,
    purchase_order_id   BIGINT,

    principal           BIGINT       NOT NULL DEFAULT 0,     -- 【契约】借据本金（整数日元）
    due_date            DATE,                                -- 【契约】合同到期日（= maturity_date）
    status              VARCHAR(16)  NOT NULL DEFAULT 'DRAFT',-- 【契约】借据状态
    created_at          TIMESTAMPTZ  NOT NULL DEFAULT now(), -- 【契约】创建时间

    -- 期限（权威源；maturity_date 与 due_date 同值，保留兼容设计稿引用）
    disbursed_at        TIMESTAMPTZ,
    maturity_date       DATE,
    grace_period_days   INT          NOT NULL DEFAULT 0,
    overdue_rate        NUMERIC(10,6),
    term_source         VARCHAR(16)  NOT NULL DEFAULT 'UNKNOWN',
    term_confirmed_by   VARCHAR(64),
    term_confirmed_at   TIMESTAMPTZ,

    -- 四项分项余额（四级冲抵顺序）
    principal_outstanding BIGINT NOT NULL DEFAULT 0,
    interest_outstanding  BIGINT NOT NULL DEFAULT 0,
    penalty_outstanding   BIGINT NOT NULL DEFAULT 0,
    fee_outstanding       BIGINT NOT NULL DEFAULT 0,

    -- 逾期当前状态
    current_dpd         INT      NOT NULL DEFAULT 0,
    current_stage_code  VARCHAR(16),
    overdue_since       DATE,
    max_dpd_ever        INT      NOT NULL DEFAULT 0,
    overdue_count       INT      NOT NULL DEFAULT 0,
    current_stage_entered_at TIMESTAMPTZ,

    -- 扣款失败当前状态
    deduction_fail_streak  INT NOT NULL DEFAULT 0,
    deduction_fail_total   INT NOT NULL DEFAULT 0,
    last_deduction_fail_at TIMESTAMPTZ,
    last_deduction_fail_code VARCHAR(24),

    -- 违约当前状态
    default_flag        BOOLEAN NOT NULL DEFAULT FALSE,
    defaulted_at        TIMESTAMPTZ,
    default_reason_code VARCHAR(32),
    default_cured_at    TIMESTAMPTZ,

    version             INT      NOT NULL DEFAULT 0,
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_loans_vin_active ON loans (vin)
    WHERE status IN ('DRAFT','ACTIVE','OVERDUE','SETTLING');
CREATE INDEX IF NOT EXISTS idx_loans_advance   ON loans (advance_id);
CREATE INDEX IF NOT EXISTS idx_loans_dealer    ON loans (dealer_id, status);
CREATE INDEX IF NOT EXISTS idx_loans_stage     ON loans (current_stage_code, current_dpd DESC);
```

### 1.1 `status` 取值契约（payment agent 判定用）

| 值 | 含义 | payment agent 用法 |
|---|---|---|
| `DRAFT` | 放款已发起、银行未确认，债未成立 | 不应据此核销 |
| `ACTIVE` | 债存续、正常还款 | 正常核销 |
| `OVERDUE` | 逾期中 | 核销时优先冲抵罚息/利息（见四项余额） |
| `SETTLING` | 结清中 | 谨慎重复放款 |
| `SETTLED` | 终态：债权消灭 | 不再产生新的还款义务 |
| `DEFAULTED` | 终态：转违约处置 | 回款走处置清偿，不是常规核销 |
| `WRITTEN_OFF` | 核销 | 同上 |

> **未结清**定义为 `status ∈ {DRAFT, ACTIVE, OVERDUE, SETTLING}`（与 `idx_loans_vin_active` 一致）。

## 2. `GET /api/loans/by-vin/{vin}` 响应结构

### 2.1 请求

```
GET /api/loans/by-vin/{vin}
Authorization: Bearer <JWT>          # 与全系统一致，/api/** 需已登录
```

- 路径参数 `vin`：`VARCHAR(32)`，大小写敏感的精确匹配。
- 无权限点要求（项目口径：读接口对所有已登录用户开放）。

### 2.2 成功响应（HTTP 200）

外层用全系统统一的 `ApiResponse<T>`：`{ code, message, data, traceId }`。
`data` 即借据对象，字段名与 JSON 键如下（**字段名已冻结**）：

```json
{
  "code": "OK",
  "message": "OK",
  "traceId": "3f1c...",
  "data": {
    "id": 1001,
    "loanNo": "LN-20261121-0001",
    "advanceId": 5501,
    "vin": "COLA017481",
    "dealerId": 42,
    "principal": 1200000,
    "dueDate": "2026-12-21",
    "status": "ACTIVE",
    "createdAt": "2026-11-21T09:30:00+09:00",

    "currentDpd": 0,
    "currentStageCode": null,
    "maxDpdEver": 0,
    "principalOutstanding": 1200000,
    "interestOutstanding": 0,
    "penaltyOutstanding": 0,
    "feeOutstanding": 0
  }
}
```

### 2.3 `data` 字段清单（冻结）

| JSON 键 | Java 类型 | 列 | 说明 |
|---|---|---|---|
| `id` | `Long` | `id` | 借据主键 |
| `loanNo` | `String` | `loan_no` | 借据编号 |
| `advanceId` | `Long` | `advance_id` | 资金来源凭证，**可能为 null**（债成立前） |
| `vin` | `String` | `vin` | 车架号 |
| `dealerId` | `Long` | `dealer_id` | 经销商 ID |
| `principal` | `Long` | `principal` | 借据本金（整数日元） |
| `dueDate` | `LocalDate` | `due_date` | 合同到期日，序列化为 `yyyy-MM-dd`；**可能为 null**（期限未录入） |
| `status` | `String` | `status` | 见 §1.1 |
| `createdAt` | `LocalDateTime` | `created_at` | 创建时间 |
| `currentDpd` | `int` | `current_dpd` | 当前逾期天数 |
| `currentStageCode` | `String` | `current_stage_code` | `M1`/`M2`/`M3`/`M4`，未逾期为 null |
| `maxDpdEver` | `int` | `max_dpd_ever` | 历史 DPD 峰值（只增不减） |
| `principalOutstanding` | `Long` | `principal_outstanding` | 剩余本金 |
| `interestOutstanding` | `Long` | `interest_outstanding` | 剩余利息 |
| `penaltyOutstanding` | `Long` | `penalty_outstanding` | 剩余罚息 |
| `feeOutstanding` | `Long` | `fee_outstanding` | 剩余费用 |

> `application.yml` 已设 `jackson.default-property-inclusion: non_null`，故值为 null 的字段不会出现在 JSON 里；payment agent 解析时**必须容忍这些键缺失**（尤其 `advanceId` / `dueDate` / `currentStageCode`）。

### 2.4 未找到（HTTP 404）

```json
{
  "code": "LOAN_001",
  "message": "未找到该 VIN 的未结清借据",
  "traceId": "...",
  "data": null
}
```

> 查不到时**返回 404 而不是 200+null**——payment agent 应把 404 当"该 VIN 无在贷债务"处理，走人工匹配/忽略分支，而不是当作系统错误。

## 3. VIN → 借据映射规则（冻结）

1. **一笔垫款对应一个借据**：`loan.advance_id` 指向 `advances.id`，银行回调 `PAID` 确认后由 outbox 事件 `LOAN_CREATED` 触发建据（钱没到，债不成立）。
2. **一个 VIN 唯一指向一笔未结清借据**：查询限定 `status ∈ {DRAFT, ACTIVE, OVERDUE, SETTLING}`，按 `id DESC` 取最新一笔。
   - 业务上允许同一 VIN 先后有多笔债（结清后再融资、分批放款），但**同一时刻未结清的只有一笔**。
   - 若底层数据出现同 VIN 多笔未结清（脏数据），端点按 `id DESC` 取最新一笔，并在审计日志记录告警，不抛错。
3. **逾期归集**：`overdue_records` 上 `uk_overdue_loan` 保证一笔借据仅一条未结逾期记录，跨 M1→M4 是同一条记录升档，不会给同一 VIN 产生多条催收。
4. **派生标记**：VIN 台账侧的逾期标记是借据状态的派生结果，不是数据源；payment agent 不应据 VIN 台账字段自行判断债务状态，一律以本契约接口为准。

## 4. DPD 分档（供 payment agent 理解 `currentStageCode`）

按设计稿 §4.3 种子数据（1-based，自然日 `CALENDAR`）：

| DPD | `currentStageCode` | 含义 |
|---|---|---|
| 0（未逾期） | `null` | 正常 |
| 1–30 | `M1` | 早期逾期 |
| 31–60 | `M2` | 风险升高 |
| 61–90 | `M3` | 严重逾期 |
| ≥91 | `M4` | 待认定违约候选 |

> 口径来源说明见 `loan-service/HANDOFF.md`：任务卡单测提示的 `1-29/30-59/60-90/90+` 与设计稿种子数据 `1-30/31-60/61-90/91+` 在边界点上有差异，实现以设计稿为准（"按设计稿实现不要发明"），单测同时覆盖两套边界点值。
