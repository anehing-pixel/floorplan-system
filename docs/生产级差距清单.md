## 0. 总判断

代码质量与业务建模（角色/SOD/状态机/审计/错误码）明显优于工程化配套。真正的问题集中在三处：

1. **「本轮先不实现」的占位被当成了完成态**：出款是内存 Mock、银行流水是 demo 样本、借据还款计划利息恒为 0、解押只打日志、对账只比内部表。这些不是优化空间，是业务主链没通。
2. **外部现实尚未接入**：银行、征信、车管所/法务局、WMS、partner 全部由人工录入或挡板替代；DMZ 模块只有启动类 + yml。
3. **生产化配套缺位**：无容器化/健康检查/调度器/可观测性/密钥强校验；多实例前置条件未满足。

重要边界：**本文不建议继续拆 web**。web 已进程级独立，ADR-001「勿拆」仍然成立——它靠本地事务 + 行锁 + 唯一约束保证账务正确性，跨服务无分布式事务。生产化重点是补工程能力与业务闭环，不是拆模块。

## 2. 模块视角：距离生产级 / 距离现实

### 2.1 架构层（贯穿所有模块）

- **共库直写**：10 个服务同指 `jdbc:postgresql://localhost:5434/floorplan` 的 `public` schema；`FOR UPDATE`（车辆/额度）只在同库成立，**拆库当天并发控制全失效**。DB 无 HA，宕机即全系统宕机。
  证据：各服务 `application.yml`；`docs/库存融资核心系统-目标微服务架构设计.md:35`；`JdbcVehicleUnitRepository.java:161`；`JdbcCreditLineRepository.java:54`。
- **多实例三处硬伤**：`EventDispatcher` 共用 `consumer_offsets` 游标、`lock.provider=memory`、支付/回款状态在内存 Map（重启即丢）。
- **事件只通一根线**：`LOAN_CREATED` 端到端已通；`PAYMENT_MATCHED` / `COLLATERAL_CHANGED` 零调用方，`DEAD` 无人工重放。
- **权限默认放行**：138 个方法级端点 vs 98 处 `@RequirePermission`（类级注解可能覆盖部分），无注解端点只需合法 token；`JwtAuthInterceptor.java:94,184` 明确 `required.length > 0` 才检查。
- **职责重叠与多套口径**：担保登记两套端点两张表（risk 写 V10 权威源 / collateral-reg 写 V18 投影）；告警两套表（在用 `alerts` / 设计好的 `risk_alerts` 零 Java）；评分三套口径（`risk_grade`/`risk_tier`/USED 双维分）；可用额度三套表示。

### 2.2 gateway

- **确凿 bug**：`/api/dealers/**` 路由提前截走 web 的 `POST /api/dealers/{id}/bank-accounts`，credit-service 无此端点 → 经网关必 404。
  证据：`gateway/application.yml:52`；`web/.../SupplierController.java:175`；`credit-service/.../DealerController.java:41-90`。
- `/api/**` 兜底会静默吞掉忘记加具名路由的新端点；`UsedValuationController.java:33-37` 注释已自认这个坑。
- 只有路由 + `X-Request-Id`；限流/熔断/超时/重试/健康检查/灰度全无；mTLS/WAF/IP 白名单/网关层 body 限流全无；CORS `allowedOriginPatterns: "*"`。
  证据：`gateway/application.yml:16-21,22-98`；`gateway/pom.xml:16-32`。

### 2.3 web（core）

- **出款是 Mock**：`MockPaymentGateway` 用 `ConcurrentMap` 存指令，重启清空、多实例互不可见；银行入账默认 `BANK_FETCH_SOURCE=demo` 返回 3 条写死样本；附件 S3 bucket 默认空 → 回退本地磁盘，无 Object Lock，不满足金融凭证留存。
  证据：`MockPaymentGateway.java:20,48,71`；`DemoBankStatementSource.java:31-35`；`web/application.yml:121-126,156-157`。
- **全部作业手动点**：计息、库龄、风险扫描、年审扫描、对账都是 `POST /api/jobs/*`，无 Quartz/定时调度，无人值守即不执行。
  证据：`JobController.java:39-124`；全仓唯一 `@Scheduled` 在 `EventDispatcher.java:81`。
- **性能**：逐条循环写（1000 车 × 365 天 = 36.5 万次单条 INSERT）、列表全量无分页、前端每 dealer 发 2 个请求（1+2N）。
  证据：`BatchApplicationService.java:130-151,176-180`；`VehicleController.java:133-135`；`views.js:32-39`。
- **业务能力空白**：审批流、消息通知、导出打印、操作回放四类为零；`account` 视图把 JWT 原文和任意接口调试器暴露给终端用户（`views.js:1139-1141,1161-1171`）。
- 共库直写 + 唯一 Flyway 入口 + `baseline-on-migrate=true`，多实例启动争抢。

### 2.4 auth-service

- 无 MFA、密码过期/失败锁定、登录审计、SSO；`users` 表无 `failed_attempts`/`password_changed_at`；BCrypt 成本因子被当成唯一防爆破手段。
  证据：`V5__users_auth.sql:7-15`；`AuthApplicationService.java:63-68`。
- JWT 不可撤销、无 refresh、无 `jti/kid/iss/aud`；约 100 个权限点全塞进 claims 且不回查；无密钥轮换（换密钥重启即全量失效）。
  证据：`AuthApplicationService.java:48,78-93,120-136`；`Permission.java:21-376`。
- 无租户维度：`users.username` 全局唯一、角色矩阵无组织维度，dealer 子账号可见全量台账（读接口明确不设权限点）。
  证据：`AuthUser.java:12-17`；`JdbcAuthUserRepository.java:41-42`；`Permission.java:14-16`。

### 2.5 external-api（DMZ）

  证据：`ExternalApiServiceApplication.java:9,26-31`；`ADR009:27-39`。
- `partner_credentials` 存的是 keystore 引用 + 指纹，全仓零 KMS/解密代码；防重放与限流阈值仍是 `[待定源]`（ADR 建议 60 次/分 vs 表默认 300，冲突未裁决）。
  证据：`V71__integration_partners.sql:44,72-93`；`external-api/application.yml:50-53`；`ADR009:479`。
- 六张 integration 表建好但零生产/消费代码，DMZ 库与主库是互不相通的数据孤岛。
  证据：`V70__integration_schema.sql:30`；全仓 Java 对 `inbound_messages`/`outbound_tasks` 只有注释引用。

### 2.6 common

## 3. 建议动手顺序（不是排期承诺）

1. **真实出款通道 + 回款→解押→回补主链**——现在这条链靠内存存根，业务上等于没通。
2. **借据 `dueDate` 定源 + 计息实现**——否则逾期、DPD、对账整条线空转。
