### 0.1 为什么需要一份新的 ADR，而不是「走配置覆盖」

`ADR-业务口径总定源.md:294` 的原话是「后续口径走配置覆盖，不改代码、不重开待确认状态」，
`:312-313` 是「不改已执行迁移 V1–V25 / 不新增待确认状态」。这三条对**同一业务域内的参数微调**是对的，
但 USED 域的需求是**业务主体、风控范式与外部协同拓扑的整体切换**（需求书 §1.1），
表现为四类无法用「配置覆盖」容纳的变化：

| 变化类别 | 为什么配置覆盖装不下 |
|---|---|
| 新增枚举取值与新增状态（`ReleaseStatus` 加 4 态、`CustodianType` 加 2 类、`SecurityType` 加 3 种） | 配置只能改取值，不能改**状态机的合法迁移集**与 DB 约束 |
| 金额基准从「发票 × 0.90」换成「审慎值 × 分档 LTV」 | 这是账务主干取数来源的替换，穿透额度、本金、递减、对拍四条链，不是阈值调整 |
| 新增外部对手方（拍卖场、监管仓 WMS）与双向 API 契约 | 现行口径明确判定「不适用于日本新车渠道」，属于**结论级冲突**而非参数级冲突 |
| 权威回执模型从 `INTERNAL_WITNESS` 改 `PARTNER_RECEIPT` | 涉及「谁能产生结清证据」的信任模型，且要撤销 V24 当年为新车域做的折中 |

所以正确做法是：**新域另立裁决，旧域原样保留**，而不是把旧 ADR 改成一份两头都不是的文档。

## 1. 适用域声明

### 1.1 两个业务域的边界

| 判定键 | `vehicle_units.vehicle_type = 'NEW_STOCK'` | `vehicle_units.vehicle_type = 'USED'` |
| 业务 | 日本新车渠道 · 品牌授权经销商 · 厂家发票定价 · 厂家回购兜底 | 独立第三方金融/信贩 · 中古车销售业者 · 拍卖场收车 · 残值定价 · 車検証质押 + 监管仓实控 |

### 反转 #6 · 估值口径：行情/查定从「不接」变「必接」

| 项 | 内容 |
|---|---|

## 4. 治理授权与红线

### 4.1 对 `ADR:294` 的限定性授权

授权 USED 域**建立自己的待定源清单**（本文 §5：D-01~D-09 + U-01~U-08），

1. 该授权**只对 USED 域生效**，LEGACY 域一律不得借 USED 域之名重开任何已定源口径；
