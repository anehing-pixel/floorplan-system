# 全链路压测脚本（scripts/loadtest）

## 1. 选型与定位

| 项目 | 说明 |
|---|---|
| 环境探测结果 | 本机无 JMeter / k6 / locust / actionlint；Java 17、Maven 3.9、Python 3.13、Ruby（自带 YAML）可用 |
| 本次选型 | **Python 标准库脚本 `loadtest.py`，零第三方依赖**，无需 pip 安装，随时可跑 |
| 用途 | 接口容量摸底、回归压测、提交前快速验证；产出含 **TPS / RT / P99 / 容量结论** 的 Markdown 报告 |
| 适用边界 | closed-loop 单接口/单链路摸底；不替代多协议、分布式、复杂事务脚本 |
| 正式压测建议 | 若后续引入 k6 / JMeter / locust，以本脚本作为“冒烟基线”，正式报告沿用第 5 节模板 |

每台工作线程复用一个 HTTP/1.1 连接（贴近真实压测，避免建连开销掩盖服务端瓶颈）。

## 2. 环境要求

- Python 3.8+（开发验证环境：3.13.14）；**无需安装任何包**。
- 被压服务需可从施压机访问（本仓库各服务端口见 `docs/工程化配置模板.md` 第 0 节）。

## 3. 快速开始

```bash
# 例 1：网关健康检查，10 并发跑 30 秒（预热 2 秒）
python3 scripts/loadtest/loadtest.py \
  --url http://127.0.0.1:18080/api/health \
  --concurrency 10 --duration 30 --warmup 2 \
  --label "网关健康检查" \
  --out reports/gateway-health.md

# 例 2：POST JSON + 鉴权头 + 爬坡 + SLA 门禁
python3 scripts/loadtest/loadtest.py \
  --url http://127.0.0.1:8085/api/loans/query \
  --method POST --body @scripts/loadtest/payload-example.json \
  --header "Authorization: Bearer {{TOKEN}}" \
  --concurrency 20 --duration 60 --warmup 5 --ramp-up 10 \
  --sla-p99 500 --sla-error-rate 1 \
  --label "贷款列表查询" \
  --out reports/loan-query.md

# 语法检查（不真压测）
python3 -m py_compile scripts/loadtest/loadtest.py
```

`--out` 不传时自动在当前目录生成 `loadtest-report-YYYYMMDD-HHMMSS.md`，不会覆盖历史报告。

## 4. 参数说明

| 参数 | 默认 | 含义 |
|---|---|---|
| `--url` | 必填 | 目标 URL（scheme/host/port/path），query 会从报告中脱敏去除 |
| `--method` | GET | HTTP 方法 |
| `--body` | 无 | 请求体；直接字符串，或 `@文件路径`（读文件）；自动补 `Content-Type: application/json` |
| `--header "K: V"` | 无 | 自定义请求头，可重复；**Header 值不写入报告** |
| `-c/--concurrency` | 10 | 并发线程数 |
| `-d/--duration` | 30 | 正式压测时长（秒，不含预热） |
| `--warmup` | 2 | 预热时长（秒），期间请求不计数 |
| `--ramp-up` | 0 | 爬坡时长（秒），线程错峰启动，避免瞬时冲击 |
| `--timeout` | 5.0 | 单次请求超时（秒） |
| `--label` | 未命名场景 | 场景名，写入报告标题 |
| `--sla-p99` | 500 | P99 延迟 SLA（毫秒） |
| `--sla-error-rate` | 1.0 | 错误率 SLA（百分比） |
| `--out` | 时间戳文件名 | 报告输出路径 |

**退出码**：`0` = SLA 达标；`2` = SLA 未达标（可用于脚本/CI 门禁）；`1` = 参数或运行错误。

## 6. 指标口径

- **TPS**：统计窗口内成功请求数 ÷ 实际统计时长（预热期不计入）。
- **RT**：从发起请求到读完响应体的耗时（毫秒）。
- **P99**：99% 的请求 RT 低于该值，按线性插值计算；P50/P90/P95 同理。
- **成功**：HTTP 2xx；非 2xx、超时、连接异常均计失败。
- 注意：closed-loop 模式下 TPS 同时受服务端与施压端能力影响；若施压端 CPU 打满，需降并发或换机器重测，否则会误判服务端瓶颈。

## 7. 压测执行规范

1. **环境隔离**：只在预发/性能环境执行，**严禁对生产施压**；确认目标 URL hostname 无误。
2. **数据准备**：造数脱敏（不得用真实 VIN / 经销商 / 客户信息）；记录数据量级便于复现。
3. **阶梯加压**：按 `10 → 20 → 40 → 80` 逐步提升并发，每级至少稳定运行 5~10 分钟。
4. **同步观测**：每级同时看 GC 日志（见 `docs/工程化配置模板.md`）、DB 连接数、慢 SQL、队列积压（见 `docs/性能与排障指南.md`）。
5. **容量判定**：以“错误率 ≤ SLA 且 P99 ≤ SLA 的最大稳定并发”为系统容量；TPS 不再随并发增长即为拐点。
6. **清理**：压测数据打标并按要求清理；保留报告与执行计划归档，不保留敏感参数。
7. **归档**：单场景报告放 `docs/performance/reports/`，慢 SQL 执行计划按 `docs/工程化配置模板.md` 第 2.4 节归档，二者通过编号互相引用。
